## 1. Project Overview

Gen-Z Digital Storefront is a full-stack e-commerce web application: a Node.js/Express REST API backed by MySQL, and a React (Vite) single-page frontend. Customers browse products, place orders via a WhatsApp-based checkout flow, and track delivery/leave reviews. Owner/Admin (and, once Staff login is implemented, permissioned Staff) manage the product catalogue and stock (restocking is done by manual stock adjustment with a mandatory, audited reason), orders, deliveries, reviews, store settings, and staff/roles.

There is no live payment gateway or bank transfer feature anywhere in this system — checkout is WhatsApp-order-based only (see [EPIC-02](EPIC-02-Customer-Order/README.md)).

## 2. Architecture Overview

- **Backend:** Layered architecture per module — `routes/ → controllers/ → services/ → repositories/`, with Zod validators and RBAC/auth middleware wired in the routes layer. Multi-write operations use `withTransaction()`. A single central `activity-log.service.js` is the only writer to the audit trail (`activity_log` table) — no module writes its own ad-hoc audit rows.
- **Actor Identity Decision:** Wherever an action needs to record "who did this" beyond the central Activity Log (`moderation_logs`), the table uses a paired `<column>_type` / `<column>_id` design: Owner/Admin acts with `type = 'OWNER_ADMIN'` and `id = NULL` (a single shared identity, no fake Staff row); a real Staff account uses `type = 'STAFF_ADMIN_USER'` with a real `staff_admin_user_id`. A database `CHECK` constraint enforces the pairing.
- **Authentication:** Two entirely separate JWT-based session types — a **Customer** session (`auth-customer.middleware.js`) and an **Owner/Admin Access Key** session (`auth-admin-access-key.middleware.js`). A `auth-staff.middleware.js` placeholder exists in code but always rejects — **Staff login is not implemented** (see [EPIC-04](EPIC-04-Store-Administration/README.md), §19).
- **Authorization:** `rbac.middleware.js` (`requirePermission(name)`) checks a Staff session's assigned role against `role_permissions`; an Owner/Admin Access Key session always passes every permission check.
- **Frontend:** React 19 + Vite, React Router 7, Axios, CSS Modules with a shared `theme.css` design-token system. No Tailwind, no TypeScript — matches the backend's plain-JS convention. Admin/Checkout/ProductDetails/Order route trees are code-split via `React.lazy`/`Suspense`. A dual-auth Axios client (`src/api/client.js`) takes an `authAs: "customer" | "admin"` option per call, reading from two separate `localStorage` tokens.

## 8. General Setup Instructions

### Backend
```bash
cd genz-backend/genz-backend
npm install
cp .env.example .env
node server.js
```

### Frontend
```bash
cd genz-frontend
npm install
cp .env.example .env
npm run dev
```

> **Windows note:** if the project path contains an `&` character, `npm run <script>` may fail under `cmd.exe`. Invoke the underlying binary directly instead, e.g. `node node_modules/vite/bin/vite.js` instead of `npm run dev`.

See each Epic's own "How to Run / Test This Epic" section for module-specific manual test steps.

## 9. Known System-Wide Gaps

These are carried over from the individual Epic READMEs so they're visible in one place:

- **Staff login is not implemented.** Staff accounts exist in the database but have no way to authenticate (`auth-staff.middleware.js` always rejects). See [EPIC-04](EPIC-04-Store-Administration/README.md).
- **No bank transfer payment method exists anywhere.** WhatsApp ordering is the only checkout mechanism. See [EPIC-02](EPIC-02-Customer-Order/README.md).
- **No admin "find delivery by order ID" lookup endpoint.** See [EPIC-03](EPIC-03-Delivery-Review/README.md).
- **No guest cart or customer profile edit/fetch endpoints.** See [EPIC-02](EPIC-02-Customer-Order/README.md).
