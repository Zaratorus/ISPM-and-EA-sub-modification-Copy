MODULE A

Product & Catalogue Management

EP-01. The product catalogue: categories, products, their images, and a one-to-one stock ledger whose availability status is computed by MySQL itself, not by application code.

PK primary key FK foreign key mandatory FK (NOT NULL) unlabeled line = ON DELETE RESTRICT (default)

Named constraints in this module

ConstraintKindWhat it guarantees
fk_products_categoryFK · RESTRICTA category can't be deleted while products still reference it.
fk_product_images_productFK · CASCADEDeleting a product cleans up its image rows automatically.
fk_inventory_stock_productFK · RESTRICTA stock ledger row can't outlive (or precede) its product.
chk_products_price_positiveCHECKprice > 0 — enforced at the database, not just in the API.
chk_inventory_quantity_nonnegativeCHECKquantity >= 0 — stock can never go negative.
availability_statusGENERATEDComputed by MySQL as IF(quantity>0,'IN_STOCK','OUT_OF_STOCK') — impossible for stock and status to drift apart.

MODULE B

Customer & Order Management

EP-02. Customers, their carts, and the orders those carts become — every order line freezes its price at checkout, independent of later catalogue price changes.

mandatory FK nullable / conditional FK italic label = references a table drawn in another module

Named constraints in this module

ConstraintKindWhat it guarantees
fk_carts_customerFK · SET NULLNullable by design — the schema explicitly leaves room for a future guest cart; deleting a customer orphans their cart rather than destroying it.
fk_cart_items_cartFK · CASCADEA cart's line items disappear with the cart.
fk_cart_items_productFK · RESTRICTA product referenced in an active cart can't be deleted.
fk_orders_customerFK · RESTRICTOrder history can never be orphaned by deleting the customer.
fk_order_items_order / _productFK · CASCADE / RESTRICTOrder lines cascade with the order; the product they reference is protected.
chk_cart_items_quantity_positive / chk_order_items_quantity_positiveCHECKquantity > 0 on both — a zero or negative line item is impossible at the database level.
uq_cart_items_cart_product / uq_order_items_order_productUNIQUEA product can only appear once per cart / once per order — quantity is adjusted in place, never duplicated as a second row.
MODULE C

Delivery Tracking with Review Management

EP-03. What happens after an order is ready: one delivery per order, tracked through six statuses, plus verified-purchase reviews that must trace back to a real order before they're accepted.

mandatory FK nullable FK italic label = references another module's table

Named constraints in this module

ConstraintKindWhat it guarantees
fk_deliveries_orderFK · RESTRICTCombined with UNIQUE(order_id) — exactly one delivery per order, never zero-or-many silently.
fk_delivery_status_history_deliveryFK · CASCADEStatus history is scoped to its delivery and cleaned up with it.
fk_reviews_customer / _product / _orderFK · RESTRICT ×3All three must resolve to real rows — a review can't reference a customer, product or order that doesn't exist. This is what makes reviews verified-purchase, not free-text.
chk_reviews_rating_rangeCHECKrating BETWEEN 1 AND 5.
chk_moderation_logs_actor_pairingCHECKEnforces the Actor Identity rule: actor_type='STAFF_ADMIN_USER' requires a real actor_id; actor_type='OWNER_ADMIN' requires actor_id IS NULL — never both, never neither.
